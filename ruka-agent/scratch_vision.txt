6.1 WHY — kenapa tensor, kenapa bukan 'gambar'
Piksel JPEG hanyalah bytes terkompresi; untuk diproses ia harus jadi grid angka. Itu bukan formalitas:
DUA konvensi layout hidup di ekosistem dan salah tebak artinya data terpotong senyap. Setelah jadi
tensor, pertanyaan berikutnya lebih dalam: operasi apa yang cocok dengan struktur gambar? Jawaban abad
lalu — konvolusi — tetap paling ekonomis untuk menghargai satu sifat fisik piksel: TETANGGADEKAT
bermakna.
Dokumen resmi (September 2026) memakai fakta yang sama untuk menentukan biaya: gambar ≤ 384 px
kedua sisi dikonsumsi 258 token; lebih besar dipotong ubin 768×768, tiap ubin 258 token, dengan unit
potong floor(min(w,h)/1,5) — contoh resmi 960×540 = 6 ubin. Membaca aturan itu butuh pemahaman
dimensi piksel; PART ini memberi fondasinya, Part X memakainya untuk budgeting.
6.2 WHAT — layout, normalisasi, luminance
Dua keluarga konvensi: HWC (PIL/matplotlib, channels-last) dan CHW (PyTorch, kernel-C). Keduanya
benar; CAMPUR ADUK keduanya adalah sumber bug klasik lintas framework.
 HWC: (H, W, C) ↔ CHW: (C, H, W) C = 3 (RGB) atau 1 (grayscale)

def to_chw(t_hwc: np.ndarray) -> np.ndarray:
    """HWC -> CHW: (H, W, C) -> (C, H, W)."""
    if t_hwc.ndim != 3 or t_hwc.shape[2] not in (1, 3):
        raise ValueError(f"bukan tensor HWC image: shape {t_hwc.shape}")
    return np.transpose(t_hwc, (2, 0, 1))
def to_hwc(t_chw: np.ndarray) -> np.ndarray:
    """CHW -> HWC: (C, H, W) -> (H, W, C)."""
    if t_chw.ndim != 3 or t_chw.shape[0] not in (1, 3):
        raise ValueError(f"bukan tensor CHW image: shape {t_chw.shape}")
    return np.transpose(t_chw, (1, 2, 0))
def add_batch(t: np.ndarray) -> np.ndarray:
    """(C, H, W) -> (1, C, H, W). Dimensi batch SELALU eksplisit.
    Validasi bentuk CHW: channel harus di depan dan bernilai 1/3 —
    menolak tensor HWC yang terkirim diam-diam."""
    if t.ndim != 3 or t.shape[0] not in (1, 3):
        raise ValueError(
            f"butuh (C, H, W) dengan C in (1, 3), dapat {t.shape} "
            f"— kemungkinan ini tensor HWC, konversi dulu")
    return t[np.newaxis, ...]

6.3 MATH — konvolusi yang sebenarnya (cross-correlation)
Kejujuran istilah sebelum rumus: operasi 'convolution' di CNN adalah CROSS-CORRELATION —
kernel TIDAK dibalik. Semua framework melakukannya; buku-buku sering lupa menyebutnya. Bukti satu
listing: respons konvolusi pada delta adalah kernel TERBALIK urutan (test delta stamp), sedangkan
konvolusi matematis memberi kernel asli.
 y[i, j] = Σₘ Σₙ x[i+u, j+v] · w[u, v] (cross-correlation)
 H_out = ⌊(H + 2P − kH)/S⌋ + 1 W_out = ⌊(W + 2P − kW)/S⌋ + 1
– Kernel w: (C_out, C_in, kH, kW) — bobot DIBAGIPAKAI lintas seluruh gambar (parameter sharing),
itulah sumber efisiensi vs dense.
– Stride S melangkah window — S=2 memangkas keluaran hampir separuh.
– Padding P menambah bingkai nol — P=(k-1)/2 pada stride 1 mempertahankan ukuran (P=cuci tangan
agar arsitektur dalam terbaca).
– Feature map: satu bidang keluaran per pasangan (kernel-out, channel-in) — jumlahnya C_out.

def conv2d(x: np.ndarray, w: np.ndarray, stride: int = 1,
           padding: int = 0) -> np.ndarray:
    """Konvolusi (cross-correlation) 2D batch. Float32 keluar."""
    if x.ndim != 4:
        raise ValueError(f"x harus (N, C_in, H, W), dapat {x.shape}")
    if w.ndim != 4:
        raise ValueError(f"w harus (C_out, C_in, kH, kW), dapat {w.shape}")
    n, c_in, h, wd = x.shape

    c_out, w_cin, kh, kw = w.shape
    if c_in != w_cin:
        raise ValueError(
            f"channel mismatch: x punya {c_in}, kernel {w_cin}")
    if stride < 1 or padding < 0:
        raise ValueError("stride >= 1 dan padding >= 0 wajib")
    h_out = (h + 2 * padding - kh) // stride + 1
    w_out = (wd + 2 * padding - kw) // stride + 1
    if h_out < 1 or w_out < 1:
        raise ValueError(
            f"kernel ({kh},{kw}) lebih besar dari input efektif "
            f"({h + 2 * padding},{wd + 2 * padding})")
    if padding:
        x = np.pad(x, ((0, 0), (0, 0),
                       (padding, padding), (padding, padding)))
    out = np.zeros((n, c_out, h_out, w_out), dtype=np.float32)
    for i in range(h_out):
        for j in range(w_out):
            si = i * stride
            sj = j * stride
            patch = x[:, :, si:si + kh, sj:sj + kw]       # (N,C,kH,kW)
            # einsum: pasang dimensi patch dengan kernel, jumlahkan.
            out[:, :, i, j] = np.einsum("nchw,ochw->no", patch, w)
    return out

6.9 WORKED EXAMPLE — konvolusi 3×3 pada window 3×3
Input grayscale window (stride pertama, tanpa padding) dikalikan kernel Sobel-X. Semua angka dihitung
tangan sampai hasil akhir.
 window x = [[1, 1, 1], [1, 1, 1], [1, 2, 1]] w = [[-1, 0, +1], [-2, 0, +2], [-1, 0, +1]]
Jumlahkan perkalian elemen-demi-elemenem: (−1·1) + (0·1) + (+1·1) + (−2·1) + 0 + (+2·1) + (−1·1) + 0 +
(+1·1) = −1 + 1 − 2 + 2 − 1 + 1 = 0. Tepi VERTIKAL di kanan window (kolom 1→2: 1→1... sebenarnya
tidak berubah) memberi nol — benar: area tanpa perubahan horizontal memang tak terlihat Sobel-X.

+ (−2·1)+0+(+2·5) + (−1·1)+0+(+1·5) = 4 + 8 + 4 = 16 — tepi vertikal KUAT menyala. Satu kalimat
bacaan: Sobel-X adalah selisih tertimbang kolom kanan minus kolom kiri; horizontal edge (baris berubah)
memerlukan Sobel-Y. Verifikasi:

def maxpool2d(x: np.ndarray, k: int = 2, stride: int | None = None
              ) -> np.ndarray:
    """Max pooling (N, C, H, W). Default stride = k (non-overlap)."""
    if x.ndim != 4:
        raise ValueError(f"x harus (N, C, H, W), dapat {x.shape}")
    if stride is None:
        stride = k
    n, c, h, w = x.shape
    h_out = (h - k) // stride + 1
    w_out = (w - k) // stride + 1
    out = np.zeros((n, c, h_out, w_out), dtype=x.dtype)
    for i in range(h_out):
        for j in range(w_out):
            si, sj = i * stride, j * stride
            out[:, :, i, j] = x[:, :, si:si + k, sj:sj + k].max(axis=(2, 3))

def avgpool2d(x: np.ndarray, k: int = 2, stride: int | None = None
              ) -> np.ndarray:
    """Average pooling (N, C, H, W)."""
    if x.ndim != 4:
        raise ValueError(f"x harus (N, C, H, W), dapat {x.shape}")
    if stride is None:
        stride = k
    n, c, h, w = x.shape
    h_out = (h - k) // stride + 1
    w_out = (w - k) // stride + 1
    out = np.zeros((n, c, h_out, w_out), dtype=np.float32)
    for i in range(h_out):
        for j in range(w_out):
            si, sj = i * stride, j * stride
            out[:, :, i, j] = x[:, :, si:si + k, sj:sj + k].mean(axis=(2, 3))
    return out

def receptive_field(layers: list[tuple[int, int]]) -> int:
    """Receptive field kumulatif dari susunan (kernel, stride).
    RF bertambah: RF_{l+1} = RF_l + (k_l - 1) * j_l,
    dengan jump j adalah hasil kali semua stride sebelum layer l.
    Contoh: dua conv 3x3 stride 1 -> RF 5; ditambah maxpool 2x2
    stride 2 lalu conv 3x3 -> RF 14.
    """
    rf, jump = 1, 1
    for k, s in layers:
        if k < 1 or s < 1:
            raise ValueError("kernel dan stride harus >= 1")
        rf += (k - 1) * jump
        jump *= s
    return rf

7.1 WHY — keterbatasan struktural CNN
CNN menghargai lokalitas: kernel kecil + pooling bertumpuk menghasilkan receptive field yang tumbuh
secara LINIER terhadap kedalaman (tabel 6.2: lima layer baru RF 13). Dua konsekuensi menghantui visi
modern: hubungan jarak-jauh antar objek (kucing DI ATAS meja) harus menunggu lapisan paling dalam;
dan resolusi input berubah RF efektifnya — gambar besar membuat objek 'lebih kecil' relatif terhadap
jangkauan.
Vision Transformer menjawab dengan langkah yang terdengar boros: potong gambar jadi patch 16×16,
perlakukan TIAP patch sebagai token (persis seperti kata di teks), dan biarkan attention global
menghubungkan semua patch sejak lapisan pertama. Jangkauan = satu lapisan = seluruh gambar. Harganya:
O(n²) pasangan patch dan kehilangan inductive bias lokal — data kecil membuat ViT kalah oleh CNN;
data besar membalikkan hasilnya. Itu temuan empiris yang stabil lintas studi; jadikan aturan praktis, bukan
iman.
