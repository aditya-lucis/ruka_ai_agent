7.3 IMPLEMENTATION — attention inti

Listing 7.1 — Scaled dot-product attention (baris 49-78 dari
src/ruka_perception/multimodal/attention.py)
def scaled_dot_product_attention(q: np.ndarray, k: np.ndarray,
                                 v: np.ndarray,
                                 mask: np.ndarray | None = None
                                 ) -> tuple[np.ndarray, np.ndarray]:
    """Attention inti. Return (output (n_q, d_v), bobot (n_q, n_k)).


--- PAGE 58 ---
    mask (n_q, n_k): 1 = boleh dilihat, 0 = diblok. Posisi 0 diberi
    skor -inf SEBELUM softmax sehingga bobotnya tepat nol.
    """
    if q.ndim != 2 or k.ndim != 2 or v.ndim != 2:
        raise ValueError("Q, K, V harus 2-D")
    n_q, d_k = q.shape
    n_k, d_k2 = k.shape
    n_k2, d_v = v.shape
    if d_k != d_k2:
        raise ValueError(
            f"dimensi d_k Q ({d_k}) != K ({d_k2}) — QK^T tak terdefinisi")
    if n_k != n_k2:
        raise ValueError(
            f"jumlah token K ({n_k}) != V ({n_k2}) — pasangan K,V lepas")
    scores = q @ k.T / np.sqrt(d_k)             # (n_q, n_k)
    if mask is not None:
        if mask.shape != (n_q, n_k):
            raise ValueError(
                f"mask {mask.shape} != {(n_q, n_k)}")
        scores = np.where(mask > 0, scores, -np.inf)
    weights = stable_softmax(scores, axis=-1)   # baris = 1
    output = weights @ v                        # (n_q, d_v)
    return output, weights
VERIFIED — Kode ini dijalankan di lingkungan buku: 243/243 test lulus pada Python 3.12.14, NumPy 2.1.3, pytest 9.0.2 (pillow 11.3.0;
 scipy 1.14.1 untuk uji silang DCT).
Tiga keputusan menonjol: mask diterapkan SEBELUM softmax dengan −inf (posisi terblok mendapat
bobot tepat nol, bukan epsilon sisa); softmax berjalan per BARIS (axis=−1) karena tiap token penanya
punya distribusinya sendiri; dan output dihitung sebagai weights @ V — rata-rata tertimbang nilai. Validasi
bentuk di kepala fungsi (listing 2.1) mengunci kontrak tabel 7.2.

Listing 7.2 — Cross-modal attention (baris 81-106 dari src/ruka_perception/multimodal/attention.py)
def cross_modal_attention(text_repr: np.ndarray,
                          image_repr: np.ndarray,
                          temperature: float = 1.0
                          ) -> tuple[np.ndarray, np.ndarray]:
    """Text attends to Image: teks bertanya, patch gambar menjawab.
    text_repr  : (n_text, d) — token teks (embedding prompt)
    image_repr : (n_patch, d) — token patch gambar (patch embedding)
    Return: konteks (n_text, d), peta perhatian (n_text, n_patch).
    Di implementasi nyata d_v boleh != d; versi ini menyatukan d —
    bagian fusion membahas konsekuensi desain itu.
    """
    if text_repr.ndim != 2 or image_repr.ndim != 2:
        raise ValueError("representasi harus (token, dim)")
    if text_repr.shape[1] != image_repr.shape[1]:
        raise ValueError(
            f"dimensi tak cocok: teks {text_repr.shape[1]}, "
            f"gambar {image_repr.shape[1]} — butuh proyeksi dulu")
    scores = text_repr @ image_repr.T / np.sqrt(text_repr.shape[1])
    scores = scores / temperature
    weights = stable_softmax(scores, axis=-1)
    context = weights @ image_repr
    return context, weights

 scipy 1.14.1 untuk uji silang DCT).

7.6 ARCHITECTURE — multi-head secara konseptual
Produksi memakai banyak head: d_model dipecah jadi h head berdimensi d_k = d_model/h, tiap head
punya W sendiri; keluaran digabung + proyeksi. Kenapa: satu distribusi perhatian hanya bisa memilih
SATU pola relasi; beberapa head memungkinkan kelompok token memperhatikan hal berbeda bersamaan
(sintaks vs semantik; posisi vs konten). Implementasi buku tetap single-head demi keterbacaan — dan itu
dinyatakan jujur sebagai penyederhanaan, bukan kelalaian.
 MultiHead = Concat(head₁..ₕ) Wₒ dengan headᵢ = Attn(QWᵢₘ, KWᵢₖ, VWᵢᵥ)

7.10 PRODUKSI — membayar O(n²) dengan sadar
Attention penuh pada 256 patch aman; pada ribuan token ia harus DIBATASI, dan cara membatasi
menentukan karakter sistem.
– Window attention: tiap token hanya melihat tetangga w window + beberapa token global — biaya
turun linear; dipakai arsitektur visi modern untuk resolusi besar.
– Pooling token dulu: gambar besar di-downsample menpatch lebih besar (32×32) — jumlah token
turun 4× per langkah.
– Caching KV: token konteks lama dihitung sekali — kunci warisanVol I (context caching) bekerja pada
prinsip yang sama.
– Anggaran keras: n maksimum per panggilan ditulis di konfigurasi, bukan kebiasaan — lebihi
anggaran = tolak dan pecah, bukan diam-diam lambat.
Kejujuran biaya adalah bagian dari desain: tabel 7.2 eksperimen (4 token × 9 patch) sengaja kecil supaya
mekanisme kelihatan; produksi akan memilih window/patch besar SESUAI kebutuhan tugas — dan setiap
kenaikan harus dibela dengan angka kualitas, bukan selera.

8.1 WHY — satu ruang, banyak penghuni
Cross-modal attention (Part VII) menggabungkan dua representasi yang SUDAH ada di satu interaksi.
Tetapi banyak kebutuhan Ruka menuntut lebih: mencari memori visual yang mirip deskripsi teks;
mendeteksi episode audio yang cocok dengan pola interaksi lalu; mengelompokkan ingatan lintas
modalitas. Semua itu butuh representasi dari modality berbeda yang tinggal di RUANG yang SAMA sejak
awal — sehingga satu index cosine melayani semua pasangan.
Membangun ruang semacam itu tidak bisa lewat deklarasi. Dua kumpulan vektor dari dua encoder terlatih
terpisah TIDAK otomatis sejajar — 'kucing' teks dan 'kucing' gambar bisa terpisah jauh, sementara

8.2 WHAT — pasangan positif, pasangan negatif
Kontrasif membangun ruang dengan dua tekanan: pasangan positif (gambar kucing ↔ teks 'seekor kucing')
DITARIK mendekat; pasangan negatif (gambar kucing ↔ teks 'mesin mobil') DIDORONG menjauh,
dalam satu batch yang sama.
 L_i = −log ( exp(s(i,i)/T) / Σⱼ exp(s(i,j)/T) )
s(i,j) adalah similarity (cosine atau dot) pasangan ke-i melawan semua j di batch; diagonal = positif, sisanya
negatif. Rumus ini adalah softmax cross-entropy menyamar: 'klasifikasi' pasangan benar di antara N-1

Listing 8.1 — InfoNCE + gradien manual (baris 30-71 dari src/ruka_perception/multimodal/contrastive.py)
def infonce_loss(sim: np.ndarray, temperature: float = 0.07
                 ) -> tuple[float, np.ndarray]:
    """Loss InfoNCE simetris ala CLIP + gradien terhadap sim.
    sim : (N, N) — diagonal = pasangan positif; lainnya negatif.
    Return: (loss skalar, dL/dsim (N, N)).
    Turunan manual (untuk pembelajaran — implementasi nyata pakai
    autograd): L_r = -(1/N) sum_i log p_ii, p = softmax(baris i dari
    sim/T). dL_r/dsim_ij = (p_ij - 1[i==j]) / (N*T).
    """
    if sim.ndim != 2 or sim.shape[0] != sim.shape[1]:
        raise ValueError("sim harus matriks persegi (N, N)")
    if temperature <= 0:
        raise ValueError("temperature harus > 0")
    n = sim.shape[0]
    logits = sim / temperature
    p = stable_softmax(logits, axis=1)               # (N, N)
    idx = np.arange(n)
    loss_rows = -np.log(np.clip(p[idx, idx], 1e-12, 1.0))
    grad = p.copy()
    grad[idx, idx] -= 1.0
    # faktor 1/N wajib: L_r = -(1/N) sum log p_ii, z = sim/T,
    # sehingga dL/dsim_ij = (p_ij - delta_ij) / (N * T).
    # (Bug nyata yang ditangkap numerical gradient check test suite.)
    grad = grad / (temperature * n)                 # dL/dsim (baris)
    # simetris: loss total = rata (baris + kolom) / 2 — seperti CLIP
    p_t = stable_softmax(logits, axis=0)
    loss_cols = -np.log(np.clip(p_t[idx, idx], 1e-12, 1.0))
    grad_t = p_t.copy()
    grad_t[idx, idx] -= 1.0
    # dL_c/dsim juga elementwise (TANPA transpose): softmax kolom
    # menghasilkan (p_t - I)/N pada posisi (i, j) yang sama.
    # (Transpose di sini = bug nyata kedua yang ditangkap gradcheck.)
    grad_t = grad_t / (temperature * n)          # dL/dsim (kolom)
    loss = float((loss_rows.mean() + loss_cols.mean()) / 2.0)
    return loss, (grad + grad_t) / 2.0
VERIFIED — Kode ini dijalankan di lingkungan buku: 243/243 test lulus pada Python 3.12.14, NumPy 2.1.3, pytest 9.0.2 (pillow 11.3.0;
 scipy 1.14.1 untuk uji silang DCT).
Gradien dL/dsim ditulis tangan bukan gaya-gayaan: dua bug nyata draf pertama (faktor 1/N hilang;
transpose keliru pada suku kolom) tertangkap numerical gradient check dengan rtol 1e-4 — standar yang
sama dengan gradcheck Vol III. Implementasi produksi memakai autograd; versi manual adalah KURSUS
yang bisa diverifikasi, bukan pengganti.

Listing 8.2 — Score fusion + deteksi modality hilang (baris 16-51 dari
src/ruka_perception/multimodal/fusion.py)
class ScoreFusion:
    """Score-based fusion: rata-rata terbobot skor per modality.
    Skor harus KOMPARABEL (sudah dinormalkan ke [0,1] oleh pemanggil —
    modul menolak rentang liar). Bobot wajib berjumlah 1 supaya hasil
    tetap di [0,1]. Ini kandidat fusion paling murah dan paling bisa
    dijelaskan — baseline WAJIB sebelum fusion neural.
    """
    def __init__(self, weights: dict[str, float]):
        total = sum(weights.values())
        if total <= 0:
            raise ValueError("total bobot harus > 0")
        self.weights = {k: v / total for k, v in weights.items()}
    def fuse(self, scores: dict[str, float]) -> float:
        """Gabung skor per modality. Modality tanpa bobot diabaikan
        (dan dilaporkan lewat exceptions list di pemanggil)."""
        out, used = 0.0, []
        for name, w in self.weights.items():
            if name in scores:
                s = float(scores[name])
                if not (0.0 <= s <= 1.0):
                    raise ValueError(
                        f"skor {name}={s} di luar [0,1] — normalkan dulu")
                out += w * s
                used.append(name)
        if not used:
            raise ValueError("tidak ada skor yang cocok dengan bobot")
        return out
    def missing(self, scores: dict[str, float]) -> list[str]:
        """Modality berbobot tapi tak tersedia — dipakai untuk menurunkan
        kepercayaan hasil fusion, bukan untuk gagal total."""
        return [k for k in self.weights if k not in scores]

def choose_fusion_strategy(available: list[str],
                           latency_budget_ms: float,
                           interaction_needs_cross_modal: bool = True
                           ) -> str:
    """Kebijakan hybrid: pilih fusion termurah yang memadai.
    Aturan (urut kebutuhan):
      1. satu modality saja      -> 'single' (tidak perlu fusion)
      2. butuh keputusan cepat   -> 'score' (rata-rata terbobot)
      3. ranking kandidat banyak -> 'late'  (Borda)
      4. butuh interaksi token   -> 'early' / 'cross_attention'
    Ini rule-based BY DESIGN — keputusan arsitektur yang bisa
    dijelaskan lebih dulu, neural fusion belakangan (Vol III Part VI
    memberikan kerangka 9 pertanyaan sebelum memakai model).
    """
    if len(available) <= 1:
        return "single"
    if not interaction_needs_cross_modal:
        return "score" if latency_budget_ms < 400 else "late"
    return "cross_attention" if latency_budget_ms >= 400 else "early"

8.6 FAILURE MODES
Fusion dan ruang bersama punya tujuh lubang khasnya.
– Ruang kolaps pasca training lanjutan — gap positif-negatif menyusut tanpa disadari; diagnosis berkala
(8.3).
– Modality gap tak terkalibrasi: threshold global membuat recall lintas modality sepi palsu — kalibrasi
per pasangan modality (Part XV).
– Temperature tanpa pikir: T=1 pada cosine skala kecil membuat loss hampir tak berbeda antar
pasangan — training berjalan tanpa belajar.
– Skor tak ternormal di score fusion: satu modality 'melebihi suara' lain — ditolak listing 8.2.

8.8 WORKED EXAMPLE — InfoNCE 3×3 dengan pensil
Batch tiga pasangan; similarity cosine (T = 0,5): s = [[1,0; 0,5; 0,0],[0,0; 1,0; 0,25],[0,25; 0,0; 1,0]] —
diagonal positif. Hitung loss baris pertama sampai angka.
Baris-1 dibagi T: (2,0; 1,0; 0,0). Eksponen: e² ≈ 7,39; e¹ ≈ 2,72; e⁰ = 1 — jumlah 11,11. Softmax: (0,665;
0,245; 0,090). Loss baris = −log(0,665) ≈ 0,408 nat. Perhatikan si pengecoh: pasangan negatif buntu 0,5
(baris-1 kolom-2) menyerap 24,5% massa — gradien akan menekannya turun paling keras. Dua baris lain
oleh simetri berbeda: baris-2 −log(0,595) ≈ 0,52; baris-3 softmax dari (0,5; 0; 2) → (0,245; 0,090; 0,665) →
loss 0,408. Rata-rata baris ≈ 0,445; kolom simetris memberi angka sama; loss total ≈ 0,445. Bacaan
insinyur: loss kecil BUKAN berarti selesai — yang dikerjakan loss adalah GRADIEN: tiap langkah
training menurunkan s(1,2) dan s(3,1) (negatif mirip) sambil menjaga diagonal. Itulah 'kontras' dalam
kontrasif. Verifikasi:

8.9 PRODUKSI — memelihara ruang embedding jangka panjang
Ruang bersama adalah aset yang menyusut tanpa perawatan. Empat ritual pemeliharaan:
– Drift check bulanan: golden pairs lintas modality diukur cosinenya; tren menurun = mulai kolaps atau
model berganti diam-diam.
– Hard negative mining: tambahkan pasangan mirat-mirip ke batch training lanjutan — gap dijaga
tetap bermakna, bukan hanya indah.
– Index terpisah per versi + migrasi terjadwal (2.9): re-embed penuh saat ganti encoder, ukur selisih
ranking dulu.
– Kalibrasi threshold per pasangan modality: teks-gambar, teks-audio, gambar-audio punya distribusi
skor berbeda (modality gap) — satu threshold global adalah sumber recall palsu.
