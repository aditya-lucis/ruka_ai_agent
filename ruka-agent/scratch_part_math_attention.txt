2.1 WHY — satu bahasa untuk tiga dunia
Teks, gambar, dan audio tiba dalam bentuk yang sama sekali tidak kompatibel: deretan token, grid piksel,
gelombang amplitudo. Kognisi Vol III hanya mengerti satu bahasa: vektor berdimensi-d dengan geometri
jarak dan sudut. Maka lapisan persepsi punya satu tugas fundamental: menempatkan ketiga dunia itu di
RUANG yang sama sehingga pertanyaan 'seberapa mirip' menjadi pertanyaan geometri yang bisa dihitung.
Tanpa ruang bersama, sistem multimodal harus memakai aturan ad-hoc per pasangan modality (jika teks
dan gambar maka ..., jika audio dan gambar maka ...). Aturan itu meledak kombinatorial dan tak bisa diuji.
Dengan ruang bersama, satu keluarga operasi — norm, dot product, cosine, proyeksi — melayani semua
pasangan. Itulah warisan matematis Vol III yang kini menemukan medan perang sebenarnya.

2.3 MATH — geometri yang diwariskan, risiko yang baru
Vol III menetapkan tiga jawaban atas 'seberapa mirip': dot product, cosine, dan euclidean. Ketiganya tetap
berlaku — tetapi persepsi menambahkan tiga kvalifikator yang hanya muncul saat datanya lintas modality.
 cos(θ) = (x · y) / (‖x‖₂‖y‖₂) d(x, y) = ‖x − y‖₂
Kualifikator 1 — normalisasi adalah kontrak, bukan kebiasaan
Di Vol III, lupa menormalkan satu sisi mengubah ranking. Di Vol IV risikonya berlipat karena vektor dari
modality berbeda punya distribusi norm yang berbeda BY DESIGN: embedding teks terlatih pada korpus
panjang, embedding audio pada klip pendek. Membandingkan cosine dua objek dari encoder BERBEDA
tanpa mengetahui distribusi norm masing-masing adalah menimbang emas dengan timbangan sayur. Paket
ini menegakkannya di kode: similarity selalu dengan epsilon stabil, dan fusion mensyaratkan skor sudah
dinormalkan [0,1] sebelum dicampur (Part VIII).
Kualifikator 2 — modality gap itu nyata
Ruang embedding bersama TIDAK sempurna simetris: klaster teks dan klaster gambar cenderung
menempati sub-wilayah berbeda dari ruang yang sama — fenomena modality gap yang terdokumentasi
pada model kontrasif. Akibat praktisnya: cosine('foto kucing', teks 'kucing') secara sistematis lebih rendah
daripada cosine dua teks sinonim. Threshold satu angka untuk semua pasangan modality adalah kesalahan
desain; Part VIII mengukur gap ini diagnostik kolaps dan Part XV mengajarkan evaluasinya.

2.4 INTERNALS — fitur hash: jembatan murah teks → vektor
Sebelum menyentuh model embedding (butuh API), Vol IV perlu vektor teks LOKAL yang deterministik
untuk uji dan baseline — warisan hashed-trigram Vol III. Prinsipnya satu paragraf matematika yang layak
diulang karena dipakai ulang di Part VIII.
 v = ∑ hash(trigram) → v[i] ± 1, dim(v) = D ≪ |kosakata trigram|
Setiap trigram teks di-hash ke salah satu D slot dan menggeser vektor slot itu +1 atau -1 (hash bertanda).
Hasilnya vektor jarang berdimensi tetap yang bisa dibandingkan dengan cosine — akurat rendah, biaya
nyaris nol, sempurna sebagai BASELINE yang harus dikalahkan model embeddings sebelum dipercaya.
Filosofi ini diwarisi lurus dari neural/features.py Vol III dan dipertahankan di ruka-perception untuk uji
fusion.

2.8 WORKED EXAMPLE — cosine dengan pensil
Ujian keyakinan terbaik untuk konsep geometri adalah menghitungnya sekali dengan tangan. Dua vektor
representasi sederhana — hasil hash trigram dua deskripsi konten — akan dibandingkan langkah demi
langkah.
 a = (2, 0, 1, 0), b = (1, 1, 1, 0)
Langkah 1 — dot product: a · b = 2·1 + 0·1 + 1·1 + 0·0 = 3. Langkah 2 — norma: ‖a‖₂ = √(4+0+1+0) = √5
≈ 2,236; ‖b‖₂ = √(1+1+1+0) = √3 ≈ 1,732. Langkah 3 — bagi: cos θ = 3 / (2,236 × 1,732) = 3 / 3,873 ≈
0,775. Langkah 4 — sudut: θ ≈ arccos(0,775) ≈ 39,2° — cukup dekat untuk disebut 'satu topik', jauh untuk
'duplikat'. Sekarang kalikan b dengan 10 (dokumen yang sama, sumber lebih 'berteriak'): dot = 30, ‖b‖ =
17,32 — cos θ TETAP 0,775. Inilah invarian yang membuat cosine layak jadi default: keputusan relevansi
tidak ikut menang siapa yang paling banyak bicara.

3.1 WHY — kenapa semua jalan lewat W
Embedding tidak jatuh dari langit. Setiap representasi yang dipakai Ruka — dari patch gambar hingga skor
relevansi konteks — adalah hasil pemetaan dari ruang input ke ruang laten. Dan bentuk paling sederhana
sekaligus paling dominan dari pemetaan itu adalah transformasi linier. Vol I memperkenalkannya sebagai
komponen neural network; Vol III melatihnya dengan backprop; Vol IV memakainya sebagai BAHASA
ARSITEKTUR: membaca bentuk W sama dengan membaca niat desain sebuah lapisan.
 y = xW + b
Persamaan itu terlihat sederhana, tetapi tiga pembacaan berbeda hidup di dalamnya — dan sistem persepsi
membutuhkan ketiganya. Sebagai feature projection: W memproyeksikan fitur mentah (mis. 26 koefisien
mel) ke ruang keputusan. Sebagai dimensionality transformation: W memampatkan 150 ribu piksel
patch menjadi 768. Sebagai representation mapping: W menerjemahkan antar ruang semantik — dari
subspace suara ke subspace identitas pembicara. Tiga nama, satu operasi; itulah kenapa aljabar bentuknya
wajib diluruskan sekali dan untuk selamanya.

3.3 WHAT — logits dan keluarga softmax
Lapisan keputusan klasik berakhir di logits: skor mentah per kelas, bisa negatif, tak berbatas. Softmax
mengubahnya menjadi distribusi probabilitas yang bisa dibandingkan dan dijumlahkan satu.
 P(i) = exp(z_i) / Σ_j exp(z_j)
Stabilisasi — kurangi maksimum dulu
exp(1000) meluap menjadi inf dalam float64. Karena softmax invarian terhadap penggeseran konstan
(mengurangi semua z dengan nilai yang sama tidak mengubah hasil), praktik yang benar selalu mengurangi
max baris sebelum exp. Listing berikut adalah implementasi paket — dua belas baris yang menanggung
beban seluruh buku.
Listing 3.1 — Softmax stabil + temperature (baris 25-48 dari
src/ruka_perception/multimodal/attention.py)
def stable_softmax(z: np.ndarray, axis: int = -1) -> np.ndarray:
    """Softmax numerik stabil: kurangi max sebelum exp.
    Invarian yang diuji: baris berjumlah 1; hasil identik dengan
    softmax naif untuk input kecil; tidak overflow pada input besar.
    """
    z = np.asarray(z, dtype=np.float64)
    zmax = z.max(axis=axis, keepdims=True)
    e = np.exp(z - zmax)
    return e / e.sum(axis=axis, keepdims=True)
def softmax_temperature(z: np.ndarray, temperature: float,
                        axis: int = -1) -> np.ndarray:
    """Softmax dengan temperature: T tinggi -> datar (eksploratif),
    T rendah -> tajam (deterministik), T -> 0 -> argmax keras.
    z/T menjaga satuan: T bukan "kreativitas", ini pembagi logit.
    """
    if temperature <= 0:
        raise ValueError("temperature harus > 0")
    return stable_softmax(z / temperature, axis=axis)

3.4 INTERNALS — entropi sebagai termometer keyakinan
Distribusi yang tajam dan yang datar sama-sama 'jumlah satu' — yang membedakan adalah tersebarnya.
Entropi mengukur itu.
 H(p) = −Σ p_i log p_i (bit bila log₂)
Vol IV memakai entropi di tiga tempat: (1) attention entropy per token — perhatian yang selalu maksimal
entropinya biasanya menandakan representasi tidak informatif (Part VII); (2) diagnosis distribusi kelas —
klasifikator yang selalu confidently wrong punya entropi rendah (Part XV evaluasi); (3) sinyal abstain —
Vol III Part VIII memakai threshold; entropi memberi versi distribusionalnya. Paket menormalkan entropi
dengan log₂(K) supaya angkanya [0,1] dan bisa dibandingkan antar jumlah kelas berbeda.

4.2 MATH — tiga rumus yang mengatur semuanya
Entropi mengukur keraguan; cross-entropy mengukur harga menebak; KL mengukur jarak antara dua
keyakinan.
 H(X) = −Σ p(x) log p(x)
 H(p, q) = −Σ p(x) log q(x)
 D_KL(p ‖ q) = Σ p(x) log (p(x) / q(x)) = H(p, q) − H(p)
– H(p) = 0 bila satu hasil pasti; maksimum log₂ K bila seragam di K kelas — entropi = jumlah
pertanyaan biner rata-rata untuk menemukan jawaban.
– Cross-entropy = loss klasifikasi: label y adalah p (one-hot), prediksi model adalah q. Meminimalkan
H(p,q) = memaksimalkan log-likelihood kelas benar — praktis sama dengan loss yang dipakai trainer
Vol III.
– KL >= 0 selalu, dan = 0 hanya bila p = q. KL TIDAK simetris: D_KL(p‖q) ≠ D_KL(q‖p) —
perhatikan arah; terbalik arah mengubah makna regularisasi.
– Hubungan ketiganya: H(p,q) = H(p) + D_KL(p‖q). Karena H(p) tetap (label tetap), menurunkan loss
= mengecilkan jarak KL prediksi ke label.
Kenapa logit 258 token per ubin itu penting
Teori informasi memberi intuisi angka resmi dari Part X nanti: satu ubin gambar 768×768 dikonversi menjadi
258 token — kompresi dari ~1,7 juta piksel RGB menjadi ratusan unit informasi yang dipilih model. Itulah
representasi: buang redundansi piksel, simpan informasi struktural. Token bukan sekadar 'unit biaya' — ia unit
INFORMASI yang dibeli.

def attention_entropy(weights: np.ndarray) -> np.ndarray:
    """Entropi baris attention (n_q,) dalam bit.
    Entropi tinggi = perhatian menyebar (kabur). Rendah = fokus.
    Dipakai observability: attention yang selalu entropi maksimal
    biasanya berarti representasi tidak informatif.
    """
    p = np.clip(weights, 1e-12, 1.0)
    ent = -(p * np.log2(p)).sum(axis=-1)
    max_ent = np.log2(max(weights.shape[-1], 2))

    return ent / max_ent          # normalisasi [0, 1] supaya bisa dibanding

Fungsi ini dipanggil observability Part XV: rata-rata entropi attention per token yang mendekati 1.0

4.4 INTERNALS — mutual information sebagai batas alignment
Konsep terakhir PART ini konseptual tetapi mendasar untuk Part VIII: mutual information I(X;Y)
mengukur berapa bit yang DIBAGIKAN dua variabel.
 I(X; Y) = H(X) − H(X | Y)
Bacaannya untuk multimodal: alignment bagus antara ruang teks dan ruang gambar berarti I meningkat —
mengetahui embedding teks memangkas keraguan tentang embedding gambar pasangannya. Loss kontrasif
InfoNCE (Part VIII) adalah batas bawah yang erat dari mutual information pasangan positif-negatif; itulah
kenapa satu kerangka matematis menjelaskan 'kenapa kontrasif bekerja' tanpa mysticism. Untuk
pengukuran literal I, diperlukan estimasi kepadatan yang mahal; praktik produksi cukup menggunakan
proxy loss — dan jujur menyebutnya proxy.

4.5 TRADE-OFFS — bit vs biaya vs kejujuran
Teori informasi menawarkan tiga jebakan praktis yang harus disebut sebelum digunakan serius.
– Entropi butuh distribusi yang benar: menghitung H dari histogram sampel kecil (mis. 5 prediksi)
menghasilkan estimasi bias ke bawah — beri sampel cukup atau jangan klaim angkanya.


--- PAGE 33 ---
– Cross-entropy menghukum kepercayaan diri yang salah secara eksponensial: log(0.01) untuk
kelas benar = kerugian besar. Itu fitur, bukan bug — tetapi bila label ber-noise, loss memberi insentif
mempelajari noise. Label smoothing (menaruh ε pada semua kelas) adalah penawar standar.
– KL bukan metrik: tak simetris dan tak memenuhi ketaksamaan segitiga. Menggunakannya sebagai
'jarak' untuk clustering = kesalahan konseptual yang biasanya berakhir menyakitkan.
4.6 FAILURE MODES
Empat wajah kegagalan alat ukur informasi.
– Confidence 0.99 + prediksi salah: entropi rendah tapi kalibrasi buruk — entropi mengukur
KERAGUAN MODEL, bukan KEBENARAN (doktrin Part III).
– Uniform karena input rusak: entropi maksimal pada gambar rusak disalahartikan sebagai 'model
bijak meragukan'. Diagnosis kualitas input harus jalan dulu.
– KL arah terbalik pada regularisasi: forward KL mass-covering vs reverse KL mode-seeking —
perilaku berbeda total pada distribusi multimodal.
– InfoNCE dibaca sebagai mutual information penuh: ia batas bawah dengan N terbatas; klaim
'mengukur MI' tanpa kualifikasi = overclaim.

4.7 WORKED EXAMPLE — cross-entropy dan KL dengan pensil
Klasifikasi 3 kelas (teks/gambar/audio) dengan label one-hot p = (1; 0; 0) dan prediksi q = (0,7; 0,2; 0,1).
Kerugian dihitung sampai kedalaman dua rumus sekaligus.
Cross-entropy: H(p, q) = −(1·log 0,7 + 0 + 0) = −log 0,7 ≈ 0,357 nat (÷ ln 2 ≈ 0,515 bit). Entropi label:
H(p) = 0 (satu pasti). KL: D_KL(p‖q) = H(p,q) − H(p) = 0,357 — semua kerugian MEMANG jarak ke
benar. Sekarang prediksi terbalik kepercayaan dirinya: q' = (0,98; 0,01; 0,01) dengan label yang SAMA: H
= −log 0,98 ≈ 0,020 — kecil. Ganti label ke kelas kedua p' = (0; 1; 0): H(p', q') = −log 0,01 ≈ 4,6 nat —
kerugian meledak 230×. Dua sifat sekaligus terlihat: cross-entropy MENGHADIAHI kebenaran percaya
diri dan MENGAZI keyakinan yang salah secara logaritmik — asimetri yang membentuk seluruh dinamika
training klasifikasi; dan log(0) → −∞ adalah alasan praktik selalu menjepit probabilitas dengan epsilon
sebelum log (listing InfoNCE Part VIII memakai clip 1e-12 persis untuk ini).

Nyquist: teorema yang menentukan 16 kHz
Frekuensi tertinggi yang bisa direkonstruksi sempurna adalah f_s/2. Manusia berbicara praktis di bawah 8
kHz — maka 16 kHz cukup untuk speech (itu alasan kontrak Live API). Musik butuh 20 kHz → 44,1 kHz.
Melanggar Nyquist tidak menghasilkan kesalahan yang terlihat; ia menghasilkan ALIASING: frekuensi
tinggi menyamar menjadi frekuensi rendah yang tidak pernah ada — korupsi senyap yang paling ditakuti.
 f_alias = |f − k · f_s| ≈ frekuensi palsu yang muncul
Kuantisasi: 16 bit artinya apa

Setiap sampel disimpan sebagai bilangan bulat 16-bit: 65.536 level antara −32768 dan +32767. Kuantisasi
seragam menambah noise ~6 dB per bit (SNR teoretis ≈ 6.02 · B dB). 16 bit memberi ~96 dB — jauh di
bawah dengar manusia untuk speech. Listing kuantisasi paket menyimpan logika ini agar bisa diuji: nilai
harus jatuh persis di grid step = 2/2^B.
5.3 MATH — dari domain waktu ke frekuensi
Satu frame 25 ms (400 sampel) hanyalah 400 angka. DFT mengatakan: 400 angka itu ekuivalen dengan
jumlah gelombang cosinus murni pada frekuensi tertentu — Fourier memberi kacamata lain untuk benda
yang sama.
 X[k] = Σₙ x[n] · e^(−j2πkn/N), k = 0..N/2 (rFFT, sinyal real)
Kenapa rFFT cukup: untuk sinyal nyata, spektrum simetris di sekitar nol — simpan setengah, sisanya
cermin. Konsekuensi yang wajib dipegang saat menghitung energi total: Parseval untuk setengah spektrum
mengharuskan mengoreksi komponen DC dan Nyquist. Test paket menuntung invarian ini persis:
 2 Σ_k |X[k]|² − |X[0]|² − |X[N/2]|² = N · Σₙ (xₙ wₙ)²
Spektrogram = gambar dari suara
Satu frame memberi satu kolom frekuensi. Jendela yang meluncur tiap 10 ms memberi ratusan kolom per
detik. Susunan kolom-kolom itu adalah SPEKTROGRAM — representasi waktu-frekuensi yang membuat
harmonik dan formant kelihatan seperti gambar. Seluruh speech recognition klasik dan banyak modern
berdiri di atas representasi ini.
Window Hann — kenapa tidak potong saja
Memotong sinyal secara tiba-tiba di tepi frame sama dengan mengalikan dengan kotak — dan kotak di
domain waktu menyebarkan energi ke SELURUH frekuensi (leakage). Hann merundukkan tepi ke nol
secara mulus, menukar resolusi sedikit dengan kebersihan spektrum. Harga resminya: energi efektif
jendela = Σ w² ≈ 0,375N — sudah termasuk dalam invarian Parseval di atas.

def frame_signal(x: np.ndarray, frame_ms: float = 25.0,
                 hop_ms: float = 10.0, rate: int = 16000
                 ) -> np.ndarray:
    """Potong sinyal jadi frame tumpang tindih.
    Return (n_frames, frame_len). Frame terakhir yang tidak utuh
    DIBUANG (konvensi umum) — jumlahnya dilaporkan di catatan modul,
    bukan diam-diam di-zero-pad.
    """


--- PAGE 38 ---
    if len(x.shape) != 1:
        raise ValueError("input harus 1-D")
    frame_len = int(rate * frame_ms / 1000.0)
    hop_len = int(rate * hop_ms / 1000.0)
    if frame_len < 2 or hop_len < 1:
        raise ValueError("frame/hop terlalu kecil")
    n_frames = 1 + (len(x) - frame_len) // hop_len
    if n_frames < 1:
        raise ValueError(
            f"sinyal {len(x)} sampel lebih pendek dari satu frame "
            f"{frame_len} sampel")
    idx = np.arange(n_frames)[:, None] * hop_len + np.arange(frame_len)[None, :]
    return x[idx].astype(np.float32)
def hann_window(frame_len: int) -> np.ndarray:
    """Window Hann: w[n] = 0.5(1 - cos(2 pi n / (N-1))).
    Endpoint 0 — mencegah diskontinuitas saat FFT."""
    n = np.arange(frame_len)
    return (0.5 * (1.0 - np.cos(2 * np.pi * n / (frame_len - 1)))
            ).astype(np.float32)
def rms(x: np.ndarray) -> float:
    """Root-mean-square: energi rata-rata sinyal/frame."""
    return float(np.sqrt(np.mean(np.square(x.astype(np.float64)))))
def to_db(x: np.ndarray, floor_db: float = -80.0,
          reference: float | None = None) -> np.ndarray:
    """Konversi amplitudo/energi ke dB. floor mencegah log(0) = -inf
    merusak visualisasi dan metrik. Referensi default = max."""
    mag = np.abs(x.astype(np.float64))
    if reference is None:
        reference = mag.max() if mag.max() > 0 else 1.0
    db = 20.0 * np.log10(mag / reference + 1e-12)
    return np.maximum(db, floor_db)

def spectrogram(x: np.ndarray, rate: int = 16000,
                frame_ms: float = 25.0, hop_ms: float = 10.0
                ) -> tuple[np.ndarray, np.ndarray]:
    """Power spectrogram via rFFT per frame.
    Return:

        freqs : (n_bins,) frekuensi pusat bin dalam Hz
    rFFT dipilih karena sinyal real: spektrum simetris, simpan setengah.
    """

    windowed = frames * win[None, :]

def hz_to_mel(f: np.ndarray | float) -> np.ndarray | float:
    """Hz -> mel (rumus 2595 log10(1 + f/700))."""
    return 2595.0 * np.log10(1.0 + np.asarray(f, dtype=np.float64) / 700.0)
def mel_to_hz(m: np.ndarray | float) -> np.ndarray | float:
    """mel -> Hz (invers persis)."""
    return 700.0 * (10.0 ** (np.asarray(m, dtype=np.float64) / 2595.0) - 1.0)
def mel_filterbank(n_filters: int, n_bins: int, rate: int,
                   fmin: float = 80.0, fmax: float | None = None
                   ) -> np.ndarray:
    """Filterbank mel: matriks (n_filters, n_bins) triangular.
    Titik-titik batas di skala mel dibagi rata; setiap filter segitiga
    menumpang dua tetangga (overlap 50% wilayah — desain standar HTK).
    Return sudah dinormalkan per filter (luas segitiga = 1).
    """
    if n_filters < 2:
        raise ValueError("minimal 2 filter")
    fmax = fmax or rate / 2.0
    if not (0 < fmin < fmax <= rate / 2.0 + 1e-9):
        raise ValueError("0 < fmin < fmax <= rate/2 wajib")
    mel_pts = np.linspace(hz_to_mel(fmin), hz_to_mel(fmax), n_filters + 2)
    hz_pts = mel_to_hz(mel_pts)
    bins = np.floor(n_bins * hz_pts / (rate / 2.0)).astype(int)
    bins = np.clip(bins, 0, n_bins - 1)
    fb = np.zeros((n_filters, n_bins), dtype=np.float64)
    for m in range(n_filters):
        left, center, right = bins[m], bins[m + 1], bins[m + 2]
        up = np.maximum(0, (np.arange(n_bins) - left) /
                        max(center - left, 1))
        down = np.maximum(0, (right - np.arange(n_bins)) /
                          max(right - center, 1))
        tri = np.minimum(up, down)
        area = tri.sum()
        if area > 0:
            tri = tri / area       # normalisasi luas
        fb[m] = tri
    return fb

    def detect(self, x: np.ndarray) -> list[tuple[int, int]]:
        """Segmen ucapan [(i_start, i_end_frame), ...] dengan histeresis.
        Aturan transisi:
          OFF->ON  : energi >= on_threshold  (dan segmen berikut cukup
                     panjang — filter min_speech_frames saat menutup)
          ON->OFF  : energi < off_threshold SELAMA hangover frames
                     berturut-turut. Satu frame bising tak menutup
                     segmen; jeda panjang menutup.

                                         self.frame_ms, self.hop_ms)

        ref = max(ref, self.noise_floor_db)

        if dynamic < self.min_dynamic_db:
            return []                    # sinyal datar: bukan ucapan
        on_thr = ref + self.on_offset_db
        off_thr = ref + self.off_offset_db
        n = len(energy_db)

        in_speech = False
        start = 0
        quiet_run = 0

5.10 WORKED EXAMPLE — DFT empat sampel dengan pensil
Sinyal terkecil yang masih bermakna: x = (1; 0; −1; 0), N = 4 — satu gelombang penuh. DFT untuk k = 1
(frekuensi satu siklus):
 X[1] = 1·e^0 + 0 + (−1)·e^(−jπ/2) + 0 × e^(−j3π/2)
Euler: e^(−jπ/2) = −j; e^(−j3π/2) = +j. Maka X[1] = 1 − (−1)(−j)·... hitung perlahan: suku-1: 1·(1+0j) = 1;
suku-2: 0; suku-3: −1 · (cos(−π/2) + j sin(−π/2)) = −1·(0 − j) = +j; suku-4: 0. Jadi X[1] = 1 + j, |X[1]| = √2
≈ 1,414. K = 0 (DC): X[0] = 1 + 0 − 1 + 0 = 0 — tidak ada komponen rata-rata. K = 2: X[2] = 1·(1) + 0 +
(−1)·(1) + 0 = 0 — frekuensi dua siklus tak hadir. Kesimpulan yang dibawa ke spektrogram: seluruh energi
sinyal hidup di SATU bin frekuensi — persis perilaku nada murni 1 kHz pada uji kalibrasi test suite
(puncak jatuh di bin 1 kHz ± 15 Hz). Verifikasi numerik dua baris:
OUTPUT
>>> x = np.array([1, 0, -1, 0])
>>> np.fft.rfft(x)
array([0.+0.j, 1.+1.j, 0.+0.j])   # X[1] = 1 + j
>>> abs(np.fft.rfft(x))**2
array([0., 2., 0.])               # energi di bin-1 saja
